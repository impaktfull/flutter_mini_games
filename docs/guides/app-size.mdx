## Only what you use

Games you don't reference are not compiled into your app. The library has no list of all games, the shared core never imports a game, and the package has no assets or fonts. Import the library and use one builder, and only that game ends up in your build.

CI checks this for every game: it builds an app per game and fails when the compiler report shows any other game in it.

## How much a game adds

Measured with `tool/check_tree_shaking.sh` (the same script CI runs): a web release build (dart2js) with Flutter 3.38. The baseline is a typical app screen: a `Scaffold` with an `AppBar`, a `ListView` and a bottom sheet (2022.6 KB, 594.9 KB gzipped). Each game is measured as that same screen with a list item that launches it.

- **Added to your app**: how much `main.dart.js` grows, including the Flutter widgets the game uses that the baseline does not
- **Package code**: the code of `flutter_mini_games` itself, from the compiler report: the shared core (screen, theme, scores, input) plus the game

A game adds **39 to 58 KB (12 to 17 KB gzipped)**. A second game adds less: the shared core (about 10 to 13 KB) and the Flutter widgets are only included once.

These are web numbers. Native (AOT) builds differ in absolute size, but the comparison between games is similar.

## Measure it yourself

```bash
tool/check_tree_shaking.sh                 # every game
tool/check_tree_shaking.sh snake sudoku    # some games
SIZE_REPORT=sizes.md tool/check_tree_shaking.sh   # also write the table as Markdown
```

Every CI run prints the table in the job summary of the tree shaking job.
